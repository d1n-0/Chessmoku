# FIVE & CROWN — 체스 × 오목

체스의 이동·포획과 오목의 연결 승리를 결합한 2인 웹게임. 흰 배경과 검정 테두리의 한국어 UI, 반응형 보드, 한 컴퓨터에서 번갈아 두는 오프라인 모드, 방 코드로 초대하는 온라인 친선전을 제공합니다.

## 실행

Node.js 22 이상:

```sh
npm ci
npm start
```

<http://localhost:3000>에 접속합니다. 개발 중 자동 재시작은 `npm run dev`입니다. 외부 CDN 없이 모든 게임 에셋을 제공합니다. 오프라인 모드는 한 컴퓨터의 브라우저에서 흑백을 모두 조작한다는 뜻이며, 최초 페이지 제공에는 로컬 서버가 필요합니다.

## Docker 배포

```sh
docker compose up -d --build
```

<http://localhost:3000>에 접속합니다. 다른 기기는 `http://서버IP:3000`으로 접속합니다. 방 코드는 같은 서버 안에서만 유효합니다. 외부 친구와 플레이하려면 서버에 접근 가능한 주소와 포트가 필요합니다.

```sh
docker compose logs -f
docker compose down
```

다른 호스트 포트는 `PORT=8080 docker compose up -d --build`로 지정합니다. `game-data` Docker 볼륨에 온라인 방 상태를 보존하므로 컨테이너를 재생성해도 복구됩니다. `docker compose down -v`는 대국 데이터를 삭제합니다.

도메인 배포에서는 Caddy/Nginx 등의 HTTPS 리버스 프록시를 앞에 두고, WebSocket Upgrade와 원래 Host 헤더를 전달하세요. 브라우저는 HTTPS에서 자동으로 WSS를 사용합니다. 예시 Caddyfile:

```caddyfile
play.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

서버는 단일 인스턴스로 운영합니다. 방 데이터는 JSON 원자적 파일 교체로 저장하며, 여러 프로세스가 같은 파일에 동시에 쓰는 구성은 지원하지 않습니다. 서버 재시작 시 클라이언트가 자동 재접속합니다. 양쪽이 오프라인인 방은 마지막 활동 후 24시간이 지나면 정리됩니다. 소규모 친선전용으로 최대 1,000개 방을 유지합니다.

## 게임 규칙

- **보드:** 8×8 보드에 백 킹 e1·흑 킹 e8 선배치, 백 선공. 각 턴에 배치 또는 이동 중 한 가지 행동.
- **초기 보관함:** 각자 폰 8, 룩 2, 비숍 2, 나이트 2, 퀸 1. 킹 1개는 이미 보드 위에 배치되어 총 16개 기물로 시작.
- **배치:** 보관함의 기물 하나를 빈 칸 어디든 배치. 배치로 포획 불가. 첫 수에도 기물 종류·진영 제한 없음.
- **이동:** 일반 체스의 기물별 이동. 나이트 외 기물은 다른 기물을 뛰어넘지 못함. 자기 기물 포획 불가.
- **포획:** 잡은 기물은 자신의 색으로 보관함에 추가. 이후 자신의 턴에 재배치 가능. 재배치한 폰의 이동 이력은 초기화.
- **폰:** 백은 8행 방향, 흑은 1행 방향으로 한 칸 전진, 대각선 앞의 적 포획. 백 2행 / 흑 7행에서 아직 이동하지 않은 폰은 경로가 비었을 때 두 칸 전진 가능. 다른 행에서는 첫 이동이어도 한 칸. 끝 행에 도달한 폰은 승격하지 않아 이동할 수 없음.
- **승리:** 종류와 관계없이 같은 색 기물을 가로·세로·대각선으로 **5개 이상** 연속 연결하거나, 상대 킹을 **실제로 포획**. 두 조건을 동시에 충족하면 킹 포획으로 표기.
- **체크:** 일반 체스의 체크 강제 대응이나 킹의 위험 칸 진입 제한은 없음. 이 게임의 체크메이트는 실제 킹 포획을 의미.
- **제외:** 프로모션, 캐슬링, 앙파상, 쌍삼 금지. 6목 이상도 승리.
- **무승부:** 다음 플레이어에게 배치·이동 가능한 행동이 없을 때. 반복수·50수 규정 및 시간제한 없음.

원 요청에서 지정하지 않은 보드 크기, 장목, 폰의 첫 두 칸 이동 등은 위 규칙으로 구체화했습니다. 킹은 처음부터 보드 위에 있으며 5목을 구성하는 기물로도 계산합니다. 색 교환이나 추가 선공 보정은 적용하지 않습니다.

## 조작 및 모드

규칙·기물 이동·에셋 출처는 `/rules.html`에 분리했습니다. 상단 규칙 링크는 새 탭에서 열려 진행 중인 대국 연결을 유지합니다.

보관함 기물을 클릭한 뒤 빈 칸을 클릭하면 배치됩니다. 내 기물을 클릭하면 이동 가능 칸이 표시됩니다. 같은 기물을 다시 누르거나 Escape를 누르면 선택을 해제합니다. 보드는 Tab 및 방향키로 탐색하고 Enter/Space로 조작할 수 있습니다.

- **오프라인:** 흑백을 같은 화면에서 번갈아 조작. 새 대국, 한 수 무르기, 보드 뒤집기, 기권, JSON 기보 저장 지원. 브라우저 localStorage에 대국을 자동 저장하고 새로고침 시 복원. 킹 선배치 도입 전 저장된 대국은 기존 배치를 유지하며, 새 대국부터 새 시작 배치를 적용.
- **친선전:** 방 생성자는 백, 6자리 코드 입장자는 흑. 양쪽 연결 후 시작. 서버가 모든 행동을 검증하고 상태 버전으로 중복·오래된 수를 거절. 다른 플레이어의 색을 클라이언트가 지정할 수 없음.
- **재접속:** 같은 탭 새로고침 시 sessionStorage의 비공개 재접속 토큰으로 복원. 상대가 일시적으로 연결을 잃으면 대국 일시 정지. 탭을 닫아 토큰을 잃으면 해당 자리 복구 불가. 방 코드는 새 자리 입장용이며 이미 찬 방의 자리를 탈취할 수 없음.
- **종료:** 진행 중 명시적으로 방 나가기/기권은 패배. 연결 끊김 자체로 자동 패배하지 않음. 재대국은 양쪽 동의 후 같은 색으로 시작하며 킹을 e1·e8에 다시 배치. 기존 온라인 방의 진행 중 대국은 유지. 결과 창을 닫은 경우 보드 아래 결과 · 재대국 버튼으로 다시 열림.

## 검증

```sh
npm test
npx playwright install chromium
npm run test:e2e
```

- 규칙 단위 테스트: 기물별 이동, 경로 차단, 폰 예외, 포획·재배치, 4방향 5목과 장목, 경계 검사, 킹 포획, 무승부.
- 실제 WebSocket 통합 테스트: 생성/입장, 정원, 차례 및 버전 검증, 재접속 인증, 디스크 복원, 양측 재대국, 나가기, cross-origin 거절.
- Playwright: 오프라인 조작·5목·무르기·새로고침·모바일 레이아웃, 독립 브라우저 두 개로 친선전·재접속·킹 포획·재대국·기권.

## 구조

```text
public/          브라우저 UI와 로컬 SVG 에셋
shared/game.js   클라이언트/서버가 공유하는 순수 규칙 엔진
server/index.js  Express 정적 파일 + WebSocket 방 서버
test/            Node 테스트 및 Playwright 시나리오
Dockerfile       비루트 사용자로 실행하는 프로덕션 이미지
compose.yaml     포트, 상태 볼륨, 재시작 및 healthcheck 구성
```

`PORT`(기본 3000), `DATA_DIR`(기본 `./data`) 환경변수를 지원합니다. 방 코드에 재접속 토큰을 포함하지 않으며 서버는 상대 토큰을 전달하지 않습니다. 데이터 디렉터리는 정적 파일로 공개하지 않습니다. 에셋의 출처 및 라이선스는 [ATTRIBUTION.md](ATTRIBUTION.md)를 참조하세요.

## 밸런스 실험

실제 서비스의 규칙을 바꾸지 않고 `scripts/balance.mjs`에서 킹 선배치와 첫 수 제한 등의 변형을 비교합니다. 연결·균형·기물 확보 성향의 봇 3종을 흑백 모든 조합으로 대전시키며, 실제로 둔 모든 수는 프로덕션 규칙 엔진과 교차 검증합니다. 별도 실험에서만 4목을 판정합니다.

```sh
# 킹 선배치 기준안과 양쪽 첫 수 자기 진영 배치안을 새 시드로 비교
node scripts/balance.mjs --variants=kings5,bothHome5 --seeds=24 --seedStart=101 --depth=4 --width=8 --workers=14 --out=analysis/balance/holdout

# 전체 집계와 그림 생성 (그림만 matplotlib 필요)
PYTHONNOUSERSITE=1 python3 scripts/summarize-balance.py
```

- [전체 집계 CSV](analysis/balance/comparison.csv), [JSON 및 전략별 결과](analysis/balance/comparison.json), [탐색 깊이별 비교 그림](analysis/balance/comparison.svg).
- 각 단계의 `*.meta.json`에는 규칙·봇 평가 가중치·시드·탐색 설정을, `*.jsonl`에는 모든 대국의 결과와 전체 수순을 저장합니다. `p@52`는 폰을 보드 인덱스 52에 배치, `60>52`는 60에서 52로 이동입니다. 인덱스 0은 a8, 63은 h1입니다.
- 시드별 기물 배치를 좌우 반사해 좌표 선택 편향을 확인합니다. 흑 선공 대조군과 색을 반전한 초기 배치의 결과도 검증합니다. 반복 키에는 보드·차례·보관함·폰 이동 이력이 포함됩니다.
- 후보를 제한하는 탐색이므로 최적 플레이를 보장하지 않습니다. 1수 탐색도 상대의 즉승 수를 피합니다. 2수 탐색은 자신의 상위 후보와 상대의 모든 답수를 정적으로 비교하고, 3수 이상은 양쪽의 상위 후보를 재귀 탐색합니다. 모든 단계에서 즉승과 즉패 수를 검사하지만 조용한 전술은 놓칠 수 있습니다.
- 동일 상태 3회 또는 120회 행동에서 **실험만 중단**합니다. 미종료를 무승부나 반 승점으로 계산하지 않으며, 백 승률의 분모에는 승패가 난 대국만 포함합니다. 고정 백 첫 수 변형의 길이는 고정 배치 이후 행동 횟수입니다.
- 초기 1~24 시드 비교 후, 최종 두 후보는 사용하지 않은 101~124 시드와 더 넓은 후보 탐색으로 재검증했습니다. 신뢰구간은 시드 단위의 대응 부트스트랩이며, 해당 봇 안의 변동성을 나타낼 뿐 사람의 승률을 뜻하지 않습니다.

이번 실험은 총 6,480판이며, 색 반전 대조 648쌍의 결과 일치를 확인했습니다. 새 시드의 최종 4수·후보 8개 비교 결과:

| 규칙 | 백 승 | 흑 승 | 실험 중단 | 결정된 대국의 백 승률 |
| --- | ---: | ---: | ---: | ---: |
| 킹 선배치·5목 | 121 | 85 | 10 | 58.7% |
| 양쪽 첫 수 자기 진영 배치·5목 | 127 | 81 | 8 | 61.1% |

두 안의 백 승률 차이(제한안 - 기준안)는 +2.3%p였고, 대응 시드 부트스트랩 95% 구간은 -2.22~+6.47%p였습니다. 추가 제한의 개선 효과를 확인하지 못했습니다. 기준안에서는 승부가 난 206판 중 킹 포획 150판, 5목 56판, 종료 행동 수 중앙값 23수였습니다. 이번 봇 실험은 5목을 4목으로 줄여야 한다는 근거를 제공하지 않았습니다.

현재 권고는 **킹 선배치·5목 유지, 추가 첫 수 보정은 보류**입니다. 백 첫 수 폰 제한은 2수 탐색에서 백 승률 46.0%였지만 3수 63.7%, 4수 72.2%로 바뀌어 안정적인 보정으로 볼 수 없었습니다. 이러한 수치는 사람의 승률이나 필승 전략의 증명이 아닙니다. 실험 당시에는 서비스 규칙을 변경하지 않았으며, 이후 킹 선배치·5목 유지안을 서비스에 적용했습니다. [최종 비교 그림](analysis/balance/holdout.svg)과 [부트스트랩 구간](analysis/balance/holdout-intervals.json)을 함께 확인할 수 있습니다.
